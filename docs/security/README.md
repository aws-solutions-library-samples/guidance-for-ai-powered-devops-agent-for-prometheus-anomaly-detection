## cdk-nag: suppressions with justification

All suppressions live in `cdk/bin/lambda-app.ts` (`NagSuppressions.addStackSuppressions(...)`). Grouped by category:

### 1. AWS-managed policies (`AwsSolutions-IAM4`)
Multiple Lambda service roles use `AWSLambdaBasicExecutionRole` (or the SageMaker equivalent). These managed policies provide standard CloudWatch Logs write access and are the AWS-documented pattern. Replacing them with hand-rolled inline copies would be the same permissions with more surface area for drift.

### 2. Wildcard permissions (`AwsSolutions-IAM5`)
- **`aps:QueryMetrics/GetLabels/GetSeries/GetMetricMetadata` on `Resource: *`** — AWS Managed Prometheus documents these query-time actions as requiring `Resource: *`. There is no resource-level ARN for query actions on APS.
- **S3 bucket-object wildcards** — `<bucket-ARN>/*` is the standard "objects in this bucket" pattern.
- **Secrets Manager suffix wildcard** — Secret ARNs get a 6-character random suffix from AWS; `secret:open5gs/devops-agent/webhook-*` is the tightest scope achievable when referencing a secret by name in IAM.
- **CDK-autogenerated `Custom::CDKBucketDeployment`** wildcards on the CDK-assets bucket — stock CDK behavior for `BucketDeployment`; we do not own that code path.

### 3. Cognito user pool (`AwsSolutions-COG2`, `AwsSolutions-COG8`)
- **No MFA** — the pool is used purely for the M2M OAuth2 client-credentials flow. There are no human users; the m2m client authenticates via `client_id` + `client_secret`. MFA does not apply.
- **Not on Plus tier** — advanced features (compromised-credentials detection, adaptive auth) target human users. Plus tier adds per-MAU cost with no security benefit here.

### 4. API Gateway (`AwsSolutions-APIG2/3/4`, `AwsSolutions-COG4`)
- **No request validation on `/mcp`** — MCP is a JSON-RPC 2.0 protocol. The JWT authorizer validates identity; the MCP Lambda validates the JSON-RPC envelope, method name, and params before dispatch. API-Gateway-level schema validation would duplicate that logic without adding security.
- **No WAFv2 on the MCP stage** — the endpoint is JWT-authorized (Cognito). WAF adds no defense against an authenticated attacker holding a valid m2m client_secret. For an unauthenticated public API, WAF would be recommended.
- **`GET /health` is intentionally public and unauthenticated** — returns a static `{"status":"healthy"}` with no data. The DevOps Agent uses it during capability-provider registration to confirm reachability before the OAuth handshake. It is not backed by application state.
- **cdk-nag doesn't recognize custom JWT authorizers as equivalent to a Cognito authorizer** (rule `COG4`). Our `/mcp` route is authorized by a Lambda `TokenAuthorizer` that validates Cognito JWTs — semantically equivalent.

### 5. Latest Lambda runtime (`AwsSolutions-L1`)
All Lambda functions in-repo use Python 3.12, the latest generally-available runtime for this ruleset. Python 3.13 is not yet a Lambda runtime option in all regions at time of writing. The CDK-autogenerated `Custom::CDKBucketDeployment` Lambda's runtime is set by the CDK library itself (not overridable from our stack).

### 6. Secrets Manager rotation (`AwsSolutions-SMG4`)
The DevOps Agent webhook secret (`open5gs/devops-agent/webhook`) holds a token that the operator generates out-of-band in the DevOps Agent console. Rotating server-side without the operator also regenerating the corresponding webhook in the Agent Space would break the pipeline. Rotation must be operator-driven, not scheduled.

### 7. S3 access logging on the notebook bucket (`AwsSolutions-S1`)
The notebook-content S3 bucket holds public architecture diagrams and the demo notebook code — all regenerated from CDK on every deploy. Contents are non-sensitive. Log storage cost is not justified.
